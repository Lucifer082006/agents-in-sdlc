GitHub Copilot をエージェントモードにすると、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行して、自律的に作業します。VS Code の Copilot Chat は、ローカルマシンでリアルタイムに進む作業を表示します。すべてのツール呼び出しとファイル編集を確認し、差分をインラインでレビューして、変更を個別に採用または却下できます。また、エディターを離れずに追加プロンプトを送信して、作業を改善したり拡張したりできます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- セッション中にエージェントへ指示し、ハイコントラストと合わせてライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を一から始める代わりに、既存のセッションに指示を加えて作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調査するファイル、実行するコマンド、提案する編集など、各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中はチャットをスクロールして、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を依頼されたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールの許可が必要な場合、エージェントは一時停止し、**Allow** の確認を表示します。許可するコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。変更内容をまとめた最後のメッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードが実装できたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは前の作業のコンテキスト (変更したコンポーネント、スタイルの方法、設定を local storage に保存する方法など) を維持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードを追加します。
3. 追加された編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる変更をしようとした場合 (たとえば、切り替え UI を望まない方法でリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すより速く作業できます。追加プロンプトで変更を依頼し ("CSS を簡素化し、セレクターを重複させず CSS 変数を使う")、方向を修正し ("3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する")、または範囲を広げられます ("両方の切り替えにキーボードショートカットも追加する")。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. いくつかの変更ファイルを開き、差分を確認します。カスタムエージェントのアクセシビリティパターンである ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定保存が反映されていることを確認します。
4. 問題がなければ Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って進行中のセッションを監視し、各ファイルの編集をレビューし、変更を採用または却下して、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 追加プロンプトを使ってセッションの作業を方向付ける。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが作成した変更をレビューします。
